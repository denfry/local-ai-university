# How mastery works

## The core rule

**An LLM is never allowed to assign its own mastery score.** Mastery is a
number computed by the system from objective evidence: test results,
SymPy/numeric checks, and exam outcomes. The Critic role is explicitly
forbidden from setting a final mastery value — it only feeds analysis
into the mastery engine.

This matters because self-reported LLM confidence is not a reliable proxy
for actual competence, and the entire point of this project is to track
*verified* learning progress, not vibes.

## What feeds the score

- **Volume and pass rate** of attempts, weighted by problem difficulty —
  five easy passes should not outweigh two failed hard problems the way
  a naive average would.
- **Recency** — older evidence decays in influence so mastery reflects
  current standing, not a peak from months ago.
- **Transfer performance** — problems that require applying a concept in
  an unfamiliar framing count for more than problems that closely mirror
  a worked example, since transfer is stronger evidence of understanding.
- **Exam results** (see below) are weighted more heavily than ordinary
  practice results, because they're taken without hints or memory.

## Sub-dimensions

Rather than a single opaque number, mastery is tracked across:

- **understanding** — can the Student explain the concept correctly?
- **implementation** — can the Student produce correct working code?
- **debugging** — can the Student find and fix a seeded bug?
- **explanation** — can the Student teach the concept back clearly?
- **transfer** — can the Student apply it in a new context?

The overall `mastery` field is derived from these, not a replacement for
them — a skill can be "mastered" on implementation but weak on
explanation, and the Obsidian note should be able to show that.

## Confidence, and why one solved problem isn't enough

`confidence` tracks how much evidence backs the `mastery` number. With
a single data point, confidence must stay low regardless of the outcome
— a 90% mastery score after one solved problem should be structurally
impossible in this system, and this is expected to be covered directly
by unit tests on the mastery formula once implemented (see
docs/development.md).

## Exam mode and why it's isolated

`aiu exam <topic>` runs with:

- no access to past solutions or notes (episodic memory disabled),
- the Teacher disabled (no fresh lesson to lean on),
- no web access,
- no hints,
- new problems generated by the Examiner, distinct from practice
  examples,
- hidden tests the Student never sees.

Without this isolation, a high score would only prove the Student can
recall or pattern-match against material it just studied, not that it
actually holds up under conditions resembling unfamiliar problems. Exam
results are weighted more heavily in the mastery update specifically
because they're harder to inflate.
